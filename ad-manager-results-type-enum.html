② 自定义转化 CUSTOM · 无限

客户自建的转化事件，名字随意（也可能只有数字 id）。无法穷举 → 需要兜底显示规则。下面 4 个方案用真实例子演示，请 PM 挑一个。

已选定

方案 A · 统一标签

全部自定义转化都显示同一个词，不区分。最保守。

…fb_pixel_custom.GSHK-Award-Submit→Custom Conversion
…fb_pixel_custom.purchase→Custom Conversion
…custom.3088433004699049→Custom Conversion

方案 B · 剥前缀 + Title-Case

去掉命名空间前缀，事件名转人类可读。信息最全，但纯数字 id 会露丑。

…fb_pixel_custom.GSHK-Award-Submit→GSHK Award Submit
…fb_pixel_custom.purchase→Purchase
…custom.3088433004699049→3088433004699049 ⚠

方案 C · 智能兜底（B 改良）

可读名 → Title-Case；纯数字/不可读 id → 退回 “Custom Conversion”。兼顾可读与不露丑。这条规则同时也兜底所有「未来新标准类型」。

…fb_pixel_custom.GSHK-Award-Submit→GSHK Award Submit
…fb_pixel_custom.purchase→Purchase
…custom.3088433004699049→Custom Conversion

方案 D · 加 “Custom:” 前缀

在 C 基础上显式标注，避免和标准事件混淆。

…fb_pixel_custom.GSHK-Award-Submit→Custom: GSHK Award Submit
…fb_pixel_custom.purchase→Custom: Purchase
…custom.3088433004699049→Custom Conversion

③ 未来 / 未知类型 FALLBACK · 保证齐全

这条让清单永远「齐全」： Meta 时不时新增优化目标。凡是没进上面固定表的标准类型，一律走方案 A 同款规则，统一显示 “Custom Conversion”，不做剥前缀/Title-Case。 → 好处：即使明天 Meta 冒出个 new_awesome_goal，也不会显示原始 id，永远不会错标成 Impressions/Engagements（现在的 objective 兜底会）；坏处：看不出具体是哪个新类型，只知道"有一个未分类的结果"——如果后续发现这类情况频繁出现、需要拆分辨认，再考虑升级到方案 B/C。
进阶选项（方案 E，成本更高）： 数字 id 那类能通过 Meta custom_conversions 接口换成客户起的真名，需多一次接口调用 + 落库缓存。当前已选定方案 A，暂不需要，等有需求再评估 E。

需要 PM 拍板

  • 决策 1（固定文案）：已选定 “Purchases”（简洁版，不用贴近 Meta 界面的 “Website Purchases”）。
  • 决策 2（自定义 + 兜底规则）：已选定 方案 A · 统一标签——所有自定义转化事件和未来/未知的新增类型统一显示 “Custom Conversion”，不做剥前缀/Title-Case 处理。
