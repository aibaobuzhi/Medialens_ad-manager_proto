LEADER DECISION MEMO · US UNATTENDED PAYMENT

美国智能柜支付 POS 选型调研

不是购买智能柜或零售 SaaS，而是在自研柜体上接入一台可用于美国无人场景、支持预授权与最终扣款的支付 POS。

候选：Adyen / Stripe / Nayax / Cantaloupe排除：365 整柜方案价格分证据等级重点：预授权增额风险

01｜结论与边界

本报告只回答支付 POS 选型

推荐
Adyen S1U2

支付编排能力最完整，官方直接提供 autonomous store 的预授权、调额与捕获流程。

低成本备选
Stripe UX700

标准费率透明、无月费、API 好；但必须书面确认本 MCC 可做增量授权。

快速接入
Nayax VPOS

硬件、联网和收单打包，部署快；费率通常高于直接 PSP，且支付状态控制较弱。

不优先
Cantaloupe

更适合传统 vending 运营商；约 5.95% 的行业披露费率对 $12 智能柜客单不经济。

建议采用“两阶段决策”

先用 Adyen 与 Stripe 做技术 POC；同时向 Nayax 获取正式报价。若 Adyen 能通过商务准入并书面确认目标 MCC/卡种的调额能力，选 Adyen；若增量授权不是硬需求或可通过动态预授权控制风险，选 Stripe 降低 TCO；只有当团队希望把终端联网、SIM、收单和设备支持一起外包时才选 Nayax。

365 Retail Markets 已移出候选：PicoCooler Vision 是整柜/平台方案，不符合“我方自行制造和维护柜体，只接支付 POS”的架构。Cantaloupe 仅保留其独立 ePort POS 方案，不讨论 Smart Store。

02｜正确比较框架

比较支付层，而非整套智能零售能力

我方负责

  • 柜体、门锁、电源与网络主控
  • 相机、AI 识别、购物 session
  • 商品、订单、税费、收据与客服
  • 设备监控、现场维护与库存

供应商必须提供

  • 美国无人支付认证终端
  • EMV / contactless / Apple Pay / Google Pay
  • 预授权、调额、捕获、撤销、退款
  • API、webhook、token、结算与争议
  • 终端远程更新、PCI 与安全支持

评分权重

  • 支付流程与异常恢复：30%
  • 美国无人硬件与供货：20%
  • API / 数据控制：20%
  • 三年 TCO：20%
  • SLA / 商务弹性：10%

所有分数只针对当前架构，不评价供应商整体实力。

05｜三年 TCO 模型

单柜、每月 600 单；不含我方柜体/CV/运维

场景 A：均单 $4

GMV = $2,400/月
  • Stripe：$94.80/月；三年 + 终端约 $3,962
  • Nayax：$69.99–152.79/月；三年 + 终端约 $2,809–5,900
  • Cantaloupe：约 $152.75/月；三年 + 硬件约 $5,789–5,899
  • Adyen：待正式 interchange/markup 报价后计算

场景 B：均单 $12

GMV = $7,200/月
  • Stripe：$224.40/月；三年 + 终端约 $8,627
  • Nayax：$189.99–438.39/月；三年 + 终端约 $7,129–16,181
  • Cantaloupe：约 $438.35/月；三年 + 硬件约 $16,070–16,180
  • Adyen：待报价；盈亏平衡需低于 Stripe 约 $224/月

场景 C：均单 $25

GMV = $15,000/月
  • Stripe：$435/月；三年 + 终端约 $16,209
  • Nayax：$384.99–902.49/月；三年 + 终端约 $14,149–32,889
  • Cantaloupe：约 $902.45/月；三年 + 硬件约 $32,778–32,888
  • Adyen：高 GMV 下最值得谈 Interchange++ 定制价

模型假设：600 笔/月、国内卡、无退款/拒付/国际卡/P2PE附加费；Stripe 按 2.7% + 5¢；Nayax 按公开区间 2.5%–5.95% + $9.99/月；Cantaloupe 按行业披露 5.95% + $9.95/月；硬件不计融资成本。实际费率以合同为准。

成本含义

若真实客单接近 $12–25，按收入比例收费的 Nayax/Cantaloupe 会迅速拉大长期成本；直接 PSP 更合理。只有在小规模、低客单、团队不愿维护支付终端联网时，打包平台的便利性才可能覆盖费率差。Adyen 必须拿到正式报价后，才能与 Stripe 做最终经济性排序。

06｜逐家分析：真正需要验证什么

以自研柜体的集成责任为中心

Adyen S1U2｜能力首选

为什么适合

  • 官方 autonomous stores 流程直接命中
  • 调额失败后可捕获原授权，并以 token 追收
  • 同步/异步 adjustment 与 webhook 清晰
  • S1U2 为嵌入式无人 Android 终端

风险

  • 美国商务准入和最低量门槛未知
  • 硬件/流量/处理费不透明
  • 授权调整仍受 MCC、卡组织、发卡行限制
  • 项目实施复杂度高于 Nayax

POC 前书面问题

目标 MCC 是什么？Visa/MC/Amex/Discover 的 card-present pre-auth 与十倍上调是否允许？debit/prepaid/wallet 如何处理？每次 adjustment 是否收费？S1U2 美国库存、RMA 和 eSIM 价格？

Stripe UX700｜成本与开发首选

为什么适合

  • 价格透明、无月费、标准 API 易集成
  • UX700 官方用于美国 unattended
  • PaymentIntent/webhook/退款/争议统一
  • 高 GMV 下明显优于 5.95% 平台费

风险

  • incremental auth 的 Terminal/MCC 适用性不清
  • UX700 价格仅有渠道披露
  • 网络、远程维护和终端故障我方承担更多
  • 可能需改变 $20 固定预授权策略

POC 前书面问题

UX700 server-driven 是否支持 manual capture + incremental authorization？哪些 card brands/funding types？失败后能否用 Terminal 保存卡做 off-session 追款？是否有授权次数/金额上限？

Nayax VPOS Touch｜最快部署

为什么适合

  • 专注 unattended，终端、SIM、收单一体
  • 公开硬件和月费，可快速买少量 POC
  • 4G 与设备遥测减少我方运维
  • MDB Level 3 面向 smart vending

风险

  • 费率取决于商品价格，可能到 5.95%
  • 更适合 vending 协议，不一定适合开放订单流
  • 调额、token、webhook 颗粒度需确认
  • 长期平台锁定与数据出口风险

POC 前书面问题

自研柜控应走 MDB、pulse 还是 API？可否传最终篮子金额？$20→$200 如何处理？最大 multi-vend/authorization cap？能否导出逐笔原始支付事件并由我方驱动退款？

Cantaloupe ePort｜对照组

保留原因

  • 美国 unattended/vending 装机与支持成熟
  • 蜂窝连接和远程遥测现成
  • 可采购、融资或零首付
  • 可作为 Nayax 的商务压价对照

不优先原因

  • 约 5.95% 费率对中高客单过重
  • 公开技术资料偏传统 vending
  • 十倍调额与开放支付编排证据不足
  • 月费、合约期和退出成本需谈判

POC 前书面问题

是否提供不绑定 Seed 运营栈的 reader/API？能否支持 basket finalization、incremental authorization、token recovery 和我方订单号？合同期、提前解约与数据导出条件？

07｜$20 预授权 → $200 最终金额

这是支付设计问题，不是单纯 POS 参数

1预授权 $20只有授权成功且卡种允许后续流程才开门。
2购物 session绑定 terminal/card alias/柜门/CV session。
3得出 $200 篮子订单先为 amount_calculated，不能显示支付成功。
4尝试调额 $200issuer 可能因金额、卡种、MCC 或风控拒绝。
5A成功后捕获收到 capture webhook 才确认结算和出最终收据。
5B失败后追收捕获可保全金额，差额进应收；以合规 token/MIT 或 payment link 追收。

不能作为承诺

任何供应商都不能保证从 $20 增至 $200 必然成功。不要把“支持 incremental authorization”等同于“所有卡、钱包和发卡行均支持十倍增额”。

产品侧控制

预授权应动态化：按柜内最高可取价值、卡种、用户历史和点位风险设置 $20/$50/$100；不支持调额的卡限制可取金额或拒绝开柜。

供应商硬 Gate

必须提供 card brand × credit/debit/prepaid × wallet × MCC 的能力矩阵，并用真实美国卡跑 $20→$21/$50/$100/$200 的成功与失败样本。

08｜POC 与决策 Gate

4 周即可淘汰不适合的方案

WEEK 1

报价与书面能力

  • 向 Adyen/Stripe/Nayax/Cantaloupe 发同一 RFP
  • 锁定 MCC、卡种、费率、硬件与 API
  • 未书面确认调额能力的方案降级
WEEK 2

台架集成

  • POS 与我方主控通信
  • 预授权、开门、调额、捕获、退款
  • webhook 幂等与断网恢复
WEEK 3

真实卡矩阵

  • 四大卡组织、debit/credit/prepaid
  • Apple Pay / Google Pay
  • $20→$0/$21/$50/$100/$200
WEEK 4

最终选择

  • 成功率、P95 延迟与异常损失
  • 100/1,000/10,000 台三年 TCO
  • SLA、RMA、合同退出和数据权
GateGo 标准淘汰条件
支付能力目标卡种预授权/调额/捕获可测、可审计；失败分支明确仅口头承诺；无法给 capability matrix；webhook 不足以对账
集成我方可驱动金额与退款，保留自有订单账本和设备控制强制采购柜体/运营平台；无法取得原始事件或数据
经济性按真实客单和单量，三年 TCO 达到毛利目标费率随 GMV 过快增长，或隐藏月费/最低量/退出费
运营美国供货、RMA、远程更新、PCI 与安全 SLA 可接受单一硬件缺货无替代；终端停产/证书到期风险不可控
