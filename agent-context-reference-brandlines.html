MediaLens Agent Reference Flow Architecture

用颜色编号追踪不同 reference object 在前端、ChatStream、ADK message、custom metadata、各 task 和多轮对话中的流转。

总流程图

从用户在 MediaLens 前端输入消息，到 ADK Runner 路由 agent、执行工具、返回 SSE typed events 的完整主链路。

Agent 框架：Harness 是什么

Harness 是包在 Agent / LLM 外面的一层工程能力。它不负责“想创意”，而是负责工具注册、权限、安全、运行、日志和结果处理。

用户 ↓ Agent / LLM ↓ Harness ├─ Tool registry ├─ Hooks ├─ Permission control ├─ Logging ├─ Execution runtime └─ Tool result handling ↓ 实际工具

在 MediaLens 中 Harness 对应什么

  • /chat/stream 接收用户请求并做鉴权、计费和上下文清洗。
  • build_message_parts 把用户文本、图片、URL-only references 组装给 LLM。
  • RunConfig.custom_metadata 把结构化上下文给工具读取。
  • Runner.run_async 负责 LLM 和工具之间的循环。
  • SSE typed events 把工具结果变成前端可渲染卡片。

为什么需要 Harness

  • 让 LLM 不直接处理权限、JWT、org id 等敏感信息。
  • 让工具拿到稳定结构化参数，而不是从自然语言里猜。
  • 让图片、Post、Brand Guideline 等上下文按固定规则进入生成流程。
  • 让所有任务都有统一的日志、事件持久化、错误处理和前端事件输出。

Agent 模块总览

将整个 agent 按可维护模块拆开：Reference 注入只是其中一个模块，另外还有 Image Gen、Post Gen、Publish、Social Pulse、Pause Ad 和 Harness 基础设施。

Reference / Prompt Context

Reference 模块

负责 upload image、selected post、quoted asset、My Page 的统一 reference pool、三通道分流、prompt 注入、多轮恢复。

  • referenceChannelRouter
  • build_message_parts
  • creative_studio_context
Brand Context

Brand Guidelines 模块

负责已确认 Brand Guideline 的保存、session 启用、品牌信息注入。它复用 Creative Studio 的结构化上下文，但不等同于 My Page。

  • creative_studio_context.brandGuideline
  • Brand Card confirmation
  • Assets -> Brand Setting
Creative Generation

Image 生成模块

消费用户 prompt、上传图、post image、asset image、My Page brand signal，调用 image-gen skill 入队。

  • image_gen_agent
  • image-gen/scripts/enqueue.py
  • image_gen_queued
Content Draft

Post 生成模块

复用 image-gen 生成视觉资产，同时生成 caption / overlay / post draft，并读取 postSettings。

  • full_post_gen_agent
  • assemble_post_draft.py
  • post_draft_created
Action Proposal

Publish 模块

从 session 找最近 draft，生成 publish intent。Agent 不直接发布，前端确认后 backend 执行。

  • propose_publish
  • publish_intent
  • frontend confirmation card
Monitoring Task

Social Pulse 模块

不走 Creative refs；从用户文本提取 keywords / platform / region / frequency，通过 MCP 创建任务。

  • social_pulse_agent
  • get_my_email
  • create_social_pulse_task
Ad Operation

Pause Ad 模块

消费 ad_manager_context，跑 ad-insights skill，生成暂停/恢复 proposal；真实写入 Meta 由确认后的 backend 完成。

  • ad_insights_agent
  • propose_ad_action
  • ad_action_proposal
Harness

ADK Harness 模块

负责 auth、billing、session、RunConfig、SSE stream、typed event 抽取、event persistence。

  • /chat/stream
  • Runner.run_async
  • DatabaseSessionService
Storage

Artifact / Session 模块

会话历史由 session events 管理；ADK artifact 是 agent/tool 文件产物，不是 Creative reference 的主通道。

  • GcsArtifactService
  • load_artifacts_tool
  • events_compaction_config
Typed Events

前端展示模块

后端从 function_response 抽取 typed events，前端渲染 queued image、draft、publish card、ad action card。

  • image_gen_queued
  • post_draft_created
  • publish_intent / ad_action_proposal

Brand Guidelines 注入逻辑

Brand Guidelines 复用现有 Creative Studio 上下文流程，但作为独立品牌上下文管理。只有用户确认后才在当前 session 生效，并可保存到 Assets -> Brand Setting。

核心原则：My Page 是 Brand Guideline 的一种来源，不是 Brand Guideline 本身。Brand Guideline 可以来自 My Page、上传 Logo/品牌图、手动填写或已有保存项。
1

需要品牌信息

Agent 判断当前任务需要品牌约束，或用户明确说“按品牌风格 / 用这个 My Page / 用我的 Logo”。

2

Brand Card 确认

若用户已有 Brand，先选择已有或新建；若选择 My Page，则先确认是否用该 Page 生成 Guideline。

3

生成 / 编辑 Guideline

LLM 可根据 My Page 或 Logo 生成草稿；用户可编辑 Brand Name、Platform、Logo、Colors、Tone、Audience。

4

用户确认

确认后保存到 Brand Setting，并写入当前 session 的 active brand context。

5

注入生成任务

Image Gen / Full Post Gen 读取 brandGuideline；Publish、Social Pulse、Pause Ad 默认不使用。

清除 / 忽略

用户说“不要用品牌风格 / 忽略这个品牌”时，本任务或当前 session 停用。

后续 session

不会默认加载，用户需要再次选择或确认 Brand Guideline。

Brand Guideline 传递什么信息

Brand Guideline 建议作为 creative_studio_context.brandGuideline 进入结构化上下文；同时在 build_message_parts 中注入一段短的品牌摘要给 LLM。

字段 来源 进入哪里 用途
brandGuideline.id 保存后的 Brand Guideline id custom_metadata.creative_studio_context 稳定识别这套品牌规则，支持后续 session 选择。
brandName 手动填写；或 My Page name 默认；或 LLM 从 Logo/图片生成 Prompt summary + structured context 告诉模型当前使用哪个品牌。
platforms[] 用户选择 My Facebook Page / My Instagram Page Structured context 未来支持同时生成 Facebook + Instagram；当前用于 page identity。
logos[] 用户上传多个 Logo / Brand image Structured context；必要时走 image reference 通道 默认作为视觉参考；用户明确要求“把 Logo 放在图里”时才作为画面元素。
colors[] 手动填写、Logo 分析、My Page 生成 Prompt summary + structured context 软约束，尽量贴合品牌色。
tone / audience LLM 生成或手动填写 Prompt summary + structured context 影响 caption、overlay text 和视觉风格。
writingRules 用户填写或 LLM 生成 Prompt summary + structured context Full Post Gen 写 caption 时遵循。

复用现有流程的方式

Brand Guideline 不需要重做一套 agent 通道。建议在现有 Creative Studio context 上扩展。

现有能力 Brand Guideline 如何复用 注意事项
creative_studio_context 新增 brandGuideline 字段，作为已确认品牌规则的结构化载体。 只传 confirmed brand；不默认加载历史 brand。
references[] My Page 仍可作为 reference，但不再直接等同 Brand Guideline。 My Page 被引用后，如果需要品牌规则，先弹 Brand Card 确认。
attachments[] Logo / Brand image 新上传时可复用 GCS upload 机制。 Logo 默认不是普通生成参考图，不一定进入 worker。
referenceImageUrls[] 当用户明确要求“图片上使用 Logo”时，把 Logo 作为 reference image 给 worker。 如果只是品牌参考，避免无标签地放入 worker，防止模型误把 Logo 画进图里。
build_message_parts 把 Brand Guideline 压缩成一段短文本注入 LLM message。 强调颜色是软约束，Logo 默认参考，不强制出现。
get_creative_studio_context() Image Gen / Full Post Gen 通过工具读取完整 brandGuideline。 工具读取结构化字段，避免让 LLM 从自然语言里猜参数。

Image Gen 与 Full Post Gen 的注入差异

同一套 Brand Guideline 在两个生成任务中的使用重点不同。

Image Gen 注入

  • 注入品牌名、颜色、视觉语气、Logo 使用规则。
  • Logo 默认是视觉参考，不强制出现在图里。
  • 如果用户说“把 Logo 放在图上”，Logo 才进入 worker reference image。
  • Brand color 是软约束，不能牺牲主体或产品表达。

Full Post Gen 注入

  • 注入品牌名、platform/page、颜色、语气、受众、写作规则。
  • 生成 caption 时遵循品牌语气和 Tone Guard。
  • 生成图片时遵循品牌视觉规则。
  • 如果同时引用竞品 Post：先保留竞品结构，再轻度套品牌。

什么时候注入 Brand Guideline

避免过度打扰，也避免用户没确认时偷偷套品牌。

场景 是否注入 说明
用户刚确认 Brand Card 是 当前 session 生效，后续 Image Gen / Full Post Gen 默认使用。
用户选择已有 Brand 是 选择后才加载，不在新 session 自动加载。
用户引用 My Page 且任务需要品牌 先确认 弹 Brand Card：是否用这个 My Page 生成 Brand Guideline。
用户上传 Logo / Brand image 先确认 LLM 生成 Guideline 草稿，用户确认后注入。
用户说“不要用品牌风格” 否 本任务临时禁用。
Publish / Social Pulse / Pause Ad 默认否 这些任务不重新生成内容或不使用 Creative refs。

0. 颜色编号图例

下面 6 类 reference object 会在整份图里使用同一套颜色和编号。

1User uploaded image

用户本地上传的图片。先上传到 GCS，聊天请求里作为 attachments[]，同时 dual-write 到 referenceImageUrls[] 给生图 worker。

2User uploaded / selected post

用户选择的 post reference。包含 post identity、caption、platform、sentiment、media、children 等结构化信息；post 主图另走 worker 图片通道。

3User quoted image

用户在 prompt 中使用 @image1 这类 marker 引用图片。可能指向上传图，也可能指向已有 asset；靠 assignedNo / refToken 绑定。

4User quoted post image

用户用 @Post 引用 post，希望参考 post 的图像和 caption。图片走 referenceImageUrls[]，caption 和 post metadata 走 references[]。

5User quoted assets

用户引用 MediaLens 内已有生成资产。CDN URL 进入 referenceImageUrls[]，结构化 asset identity 进入 references[]。

6User quoted My Page

用户引用自己的 connected page。没有图片像素通道，只进入 references[]，提供 page identity、handle、followers、brand tone 等。

橙色高亮表示最影响生成质量、最值得优化的环节。核心目标是让 LLM 和生图 worker 在当前 turn 都拿到准确、成对、结构化的 reference。

/chat/stream

优化点 C

build_message_parts

注入 [imageN]、file_data、URL-only 文本、引用图分析。这里决定 LLM 当前 turn 看见什么。

优化点 D

custom_metadata

结构化保存 creative_studio_context。工具稳定读取 ratio、postSettings、referenceImageUrls、references。

优化点 E

Sub-agent / Skill

优化点 F

  • LLM 当前 turn 看到：用户文本、上传图 file_data、URL-only refs、引用图分析、My Page brand identity。

Full Post 组装重点

  • 同一 turn 内 LLM 生成 caption / overlay text。
  • 读取 postSettings 生成 publish config。
  • 调用 assemble_post_draft.py 保存 draft，输出 post_draft_created。

建议：在 prompt 注入中显式写出“reference image 和 caption 属于同一个 selected post”。这对生成质量比让模型自己从分散字段推断更稳。

6. URL-only 文本和引用图分析从哪里来

这两类都是后端额外注入到 ADK message parts 的文本。

注入文本 来源 用途
[Some Post] — referenced Instagram post (URL-only; id: xxx) references[].name, references[].post.platform, references[].entityId 让任何 routed sub-agent 都知道用户引用的是哪个 post。这里的 URL-only 表示没有作为 file_data 给 LLM。
[image2] — generated asset (URL-only, no pixels attached): https://... referenceImageUrls[] 中非 upload 的 asset URL 和 assignedNo 让 prompt 里的 @image2 能落到某个已有 asset。
[引用图分析 Some Post] ... 后端对 post image / video cover / asset image 调视觉模型分析得到的摘要 当 LLM 没有直接拿到原图像素时，用视觉摘要补充构图、主体、色调等信息。
[My Page] — your connected Facebook page @handle ... references[] 中 page identity、handle、followers、brand 给生成任务提供品牌身份和语气，不提供图片像素。

7. My Page 字段来源

My Page 没有图片 URL 注入，主要是品牌身份和调性上下文。

字段 来源 说明
entityId MyPagePicker.vue selected page 的 page.id 稳定 page id；当前 refToken 也用这个值。
name page.name，fallback 到 page.username 用于 LLM 可读的 page 名称。
platform My Page picker 的 active platform 如 fb / ig / thread。
handle page.username 后端会注入为 @handle。
follower page.follower 作为品牌规模信号。
brand.tone/audience/colors utils/myPageBrandTone.js 固定映射表，按 handle 精确匹配 不是临时 AI 分析。tone/audience 来自 Notion 品牌调性整理，colors 来自 Notion Brand color/logo。

8. 多轮对话中的流转

ADK session history 会保留历史 events，但生成质量最好不要只依赖历史。

Turn 1
User: 用这张图生成广告
→
1 [image1] + file_data gs://...
→
ADK session events 持久化
Turn 2
User: 用回最开始的参考图重新生成
→
ADK 读取历史 events
→
历史 [image1] / file_data 可能仍在上下文
质量最稳做法
前端从历史 snapshot 恢复 image1
→
当前 turn 重新发送 attachments[]
→
当前 turn 重新发送 referenceImageUrls[]
→
LLM 和 worker 都直接拿到原图
注意：ADK session history 是正常多轮机制，但长对话会压缩或截断。对生成质量敏感的任务，不建议只依赖“历史里可能还有图片”；应该在当前生成 turn 重新发送关键 reference。

9. 生成质量建议清单

如果目标是提高 image generation / full post generation 的稳定性，优先做这些。

建议 原因 影响
当前 turn 重发关键上传图到 attachments[] 确保 LLM 直接看到原始像素，不依赖历史上下文。 提高多轮 re-gen 稳定性。
当前 turn 重发关键参考图到 referenceImageUrls[] 确保生图 worker 直接拿到参考图。 提高 img2img / clone / style match 成功率。
Post 图片和 caption 用 entityId/ref_token 显式绑定 避免模型把图片和另一个 post caption 混淆。 提高引用 post 改写质量。
在 prompt 注入中明确声明“image + caption belong to same selected post” 让 LLM 无需隐式推断跨通道关系。 降低错配概率。
My Page brand 缺失时不要猜 当前 brand tone 是固定表精确匹配，不是 AI 分析。 避免跨品牌风格污染。
不要把 CDN URL 放进 attachments[] attachments[] 是 GCS file_data 通道，只接受 gs://。 避免整条 chat request 失败。
